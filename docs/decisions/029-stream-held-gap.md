# 流式 Markdown：尾部首块的空行

- 日期：2026-10-22
- 状态：已实施
- 提交：无
- Brief：无

## 背景

主 agent 集成 [025](025-list-fence.md) 时，用边界语料比对流式和整篇渲染，发现 main 上的一处差异：段落、标题或列表后面不空行地接一个新列表，流式输出少一行空行。

- `Steps:\n- a\n- b\n`、`# H\n- a\n`、`1. a\n- b\n`、`- a\n* b\n` 有这个差异，5 种切法、匀速开和关的每种组合下复现。
- 原因：最后一个块留在尾部时，`parse` 把这个块的列表存进当前层的 `list`，供尾部渲染取序号。下一次解析从这个块开始，拿它和自己的列表比，判成同一个列表的续项，空行改按源码里有没有空行算，得 0；整篇渲染在两个块之间空一行。
- 模型的回答常写「步骤：」紧跟列表。markdown 模块没有发布过，0.2.2 第一次带上它。

## 决策

- Claude 定：这是 0.2.2 要发的模块的缺陷，按集成的授权在发版之前修。用户的授权见 [024](024-bingo-research.md) 的结果（「不拆 tokio，发 0.2.2 (Recommended)」）和 025 的方案（主 agent 集成后发 0.2.2）。
- 层（`Frame`）加一个标记 `held`：尾部的首块在留下时算好了空行和序号，存在这一层；下一次解析的第一个块沿用它们，不和存下的列表比较。其余块的算法不变。

## 备选与取舍

- **留下时不改 `list` 和 `gap`，由尾部渲染自己算**：尾部渲染要解析出首块是不是列表、用什么标记，多一次解析。
- **给留下之前的列表状态存一份副本**：改 `stable` 的每个地方要维护它；`held` 在每次解析开始时取走，设它的路径是留下块的那一条。

## 方案

主 agent 自己改，在 `wt/list-fence` 分支上 025 的提交之后：

- 改 `src/markdown/stream.rs` 的 `Frame` 和 `parse`。
- 测试：`pieces_equal_document` 的语料加三篇（段落接列表、标题接列表、两种列表相接），没有新的测试函数。
- 验收：全量测试；`markdown-stress` 复测 README 和 design.md。

## 结果

- `Frame` 加 `held`，`parse` 在每次解析开始时取走它，留下块的路径设它；design.md 的「测试」改成 71 篇。
- 语料加三篇：`Steps:\n- a\n- b\n`、`# Heading\n1. a\n`、`1. a\n- b\n`。修改之前这三篇在 `pieces_equal_document` 失败，修改之后通过；26 篇边界语料的探针通过。
- 全量：fmt、三组 feature 的 clippy、`cargo test --workspace --all-features` 和 `--features markdown --test markdown` 通过，共 142 个测试。
- 性能（`markdown-stress`，release，`markdown-highlight`，每帧 64 B，120 fps），每篇跑两次，p50 / p99 / max（ms）：

  | 文档 | 第一次 | 第二次 |
  |---|---|---|
  | README | 0.36 / 1.01 / 1.01 | 0.34 / 1.34 / 1.34 |
  | design.md | 0.37 / 1.35 / 2.48 | 0.37 / 2.04 / 8.83 |
  | 列表项里 500 行代码块 | 0.24 / 2.02 / 79.75 | 0.25 / 0.79 / 1.09 |

  两个超过 8.33 ms 的帧出现在两次运行中的一次，测量时有一个 worktree 在编译。p50 和 025 的差别在噪声范围内。
