# 升级 ink-rs 到 0.1.4

- 日期：2026-10-22
- 状态：已实施
- 提交：`de1bba4` chore(deps): update ink-rs to 0.1.4；`085cf1b` chore(deps): update tokio to 1.54.1

## 背景

ink-rs 0.1.4 让 `max_fps` 按固定节拍排帧（ink-rs 的记录 063、064）。[016](016-markdown-stream.md) 的结果写明：0.1.4 发布后本仓库升级依赖，demo 里 1ms interval 的绕法随之改写。Claude 请用户批准推送本仓库 main 的 4 个提交，「或者等 0.1.4 发布、依赖升级之后一并推送」，用户答「批准」。

## 决策

- 用户定（「批准」）：0.1.4 发布后升级依赖，和 016 的提交一并推送。
- 以下由 Claude 按同一授权定：
  - 根 crate 和 file-routes、ship、quill 三个示例 crate 的 ink-rs 要求都改为 `0.1.4`。根 crate 的用户由此拿到固定节拍；示例和根 crate 保持同一版本。
  - Markdown demo 保留 1ms interval，改写注释：0.1.4 里被窗口挡住的 tick 在窗口打开时交付，interval 不超过窗口就跑满 `max_fps`，1ms 覆盖各档帧率。时钟只在匀速揭示时运行（016 的第 3 点）属于正式实施，不在这次做。
  - `Cargo.lock` 里的 tokio 从 1.54.0 升到 1.54.1，单独提交。1.54.0 被撤回；ink-rs 发布 0.1.4 时用户为同一问题选了「升到 1.54.1」，这里照做。
  - 不发布 eink-rs。

## 备选与取舍

- **要求留在 `0.1.3`**：semver 下用户可以解析到 0.1.4，但下限 0.1.3 拿不到固定节拍，demo 的注释会失真。
- **demo 的 interval 改为 `1000 / fps` 毫秒**：效果相同，要把帧率参数传进组件，改动多于改注释。

## 方案

主 agent 自己做：

1. 四个 `Cargo.toml` 和 `Cargo.lock`；demo 的注释。
2. fmt、`--all-features` 的 clippy 和测试、`cargo build`。
3. tmux 里跑 demo，看状态栏的帧率。
4. 推送 main。
